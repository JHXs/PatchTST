## 0. 这张表解决什么问题

`docs/研究探索与实验验证工作流.md` 规定「一个想法 → 理论分支 → 消融分支 → 确认分支」，
方向一多就会产生大量分支，而工作流本身**只定义流程、不记录状态**。结果是：

- 想知道「第二创新现在到哪一步」只能 `git branch -a` 逐个考古；
- `main` 上的文档会与分支上的结论脱节（`94dd000` 修正的频域过时表述即此形态）；
- 「已登记」与「已消费」两个概念在不同分支被混用，导致资源台账互相矛盾（见 §4）。

本文件是**唯一索引**。规则：

1. 任何阶段门（放行 / 止损 / 确认提交）结束时，**必须**同步更新本表；
2. 本表中的结论必须能在指定入口文档或 commit 中直接复核；
3. 本表只记录状态，不替代分支内的协议、决策记录和结果产物；
4. 冲突未解决前，在 §5 显式登记，不擅自改写历史分支的结论。

### 风险 R3：确认阶段（`experiment/<idea>-confirmation`）从未被使用

工作流定义了三阶段，但仓库中 **0 个** `*-confirmation` 分支。唯一成立的第一创新点，
其确认是在消融分支 `experiment/st-patchtst-refix` 内完成并直接合并。
后果：确认阶段的产物（冻结的 selected commit、确认协议、预注册阈值）没有统一落点，
审计时只能回到分支内的报告去拼。

### 风险 R4：命名偏离工作流约定

工作流要求 `<idea>` 为简短稳定的 kebab-case 英文，实际有 8 个分支偏离：

| 分支 | 偏离 |
|---|---|
| `experiment/causal-multiscale-frequency` | 缺 `-ablation` |
| `experiment/deepseek-pollutant-specific-alpha` | 缺 `-ablation`，且无对应理论分支 |
| `experiment/round11-cf-cv-smearing-fixture` | 轮次命名 + `fixture` |
| `experiment/st-patchtst-refix` | 非创新点方向名 |
| `research/round13-second-innovation-space-audit` | 缺 `-theory` |
| `research/round9|10|11|12-*` | 主体为轮次号而非想法名 |

根本原因是**粒度不匹配**：工作流假设「一个想法 = 一个分支」，但 round9–round13
实际是「一轮批量出清多个机制族」（round13 单轮即审计 14 个已止损族 + 12 个封存族 + 14 个未探索族）。
这不是操作失误，见工作流 §2.1 新增的批量模式。

### 风险 R5：`main` 文档与分支结论脱节

已知实例：`AGENTS.md` 与 `plan/experiment-protocol.md` 曾写「频域分支尚未实现」，
而频域早已止损。该实例已由 `94dd000` 修正（`plan/experiment-protocol.md:97` 现为正确表述）。
但该风险是结构性的：只要分支结论不回写 `main`，就会再次发生。
本表即为回写点——阶段门结束时必须更新。
