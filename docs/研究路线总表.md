## 0. 这张表解决什么问题

`docs/研究探索与实验验证工作流.md` 规定「一个想法 → 理论分支 → 消融分支 → 确认分支」，
方向一多就会产生大量分支，而工作流本身**只定义流程、不记录状态**。结果是：

- 想知道「第二创新现在到哪一步」只能 `git branch -a` 逐个考古；
- `main` 上的文档会与分支上的结论脱节（`94dd000` 修正的频域过时表述即此形态）；
- 「已登记」与「已消费」两个概念在不同分支被混用，导致资源台账互相矛盾（见 §4）。

相关文档：`docs/提交记录中文对照表.md` 提供全部提交的中文说明（含分支↔提交↔结论速查与外部归档清单）。本表负责状态，那份文档负责“某条提交做了什么”。

本文件是**唯一索引**。规则：

1. 任何阶段门（放行 / 止损 / 确认提交）结束时，**必须**同步更新本表；
2. 本表中的结论必须能在指定入口文档或 commit 中直接复核；
3. 本表只记录状态，不替代分支内的协议、决策记录和结果产物；
4. 冲突未解决前，在 §5 显式登记，不擅自改写历史分支的结论。
