## 当前实现，而不是旧示意图

main@1a26492的run_st_patchtst_ablation.py设置patch_len=4、stride=2、d_model=16；24→1和168→6共享此默认分块尺度。ST_PatchTST_model.py从安装包tsai.models.PatchTST导入主干。

本机tsai=1.0.1；被审计文件：

`.venv/lib/python3.12/site-packages/tsai/models/PatchTST.py`

SHA256：`aed91265c11ce67001015745fd7ff3a896a30ca197700285bd074f3d814d2a2c`。

该实现的_PatchTST_backbone使用ReplicationPad1d((stride,0))，即左侧复制填充；forward无条件执行padding。保存了padding_patch属性，但这段forward没有按该属性关闭padding。W_P是Linear(patch_len,d_model)，之后加位置编码，再经编码器和Flatten_Head。

官方PatchTST supervised实现只有padding_patch=='end'时才执行ReplicationPad1d((0,stride))，即右侧复制：

https://raw.githubusercontent.com/yuqinie98/PatchTST/main/PatchTST_supervised/layers/PatchTST_backbone.py

这是**实现差异**，不自动证明本机行为错误或官方行为更准。不能直接改依赖、改变第一创新点主干或把对齐官方padding包装成第二创新。

## 纯索引检查

只构造0..L-1整数索引，不构造或读取站点观测。模拟左pad2、patch4、stride2：

| L | patch数 | 第一个patch | 最后一个patch |
|---|---:|---|---|
| 24 | 12 | [0,0,0,1] | [20,21,22,23] |
| 168 | 84 | [0,0,0,1] | [164,165,166,167] |

两种长度所有原始索引均被覆盖。索引0出现4次，索引1至L-3各2次，末两点各1次。该计数是原始patch出现次数，不是注意力权重、梯度权重或预测影响强度。

可复算：

```python
from collections import Counter
for L in (24,168):
    padded = [0,0] + list(range(L))
    patches = [padded[s:s+4] for s in range(0,len(padded)-3,2)]
    counts = Counter(i for p in patches for i in p)
    assert set(counts) == set(range(L))
    assert len(patches) == L//2
    assert counts[0] == 4 and counts[L-1] == counts[L-2] == 1
```

## 必须排除的错误前提

1. 不是长patch的非重叠分块；不能直接照搬“边界处事件被切断、没有重叠路径”的动机。
2. 最后两个时刻没有丢弃，不能宣称新增分支找回了被tokenizer漏掉的最新值。
3. 条件命题：若W_P列满秩，则每个4维patch可以从其16维线性投影恢复（减去已知偏置）；只要所有原始索引被覆盖，整个原始patch抽取＋该投影是单射。因此“stride2必然导致原始输入不可逆混叠”并不成立。
4. 第3项不是对已训练W_P秩的实测，也不涵盖RevIN未携带统计量、训练dropout、后续非线性编码或最终低维预测头。它不证明模型没有归纳偏置问题、更不证明偏移平均一定无用。
