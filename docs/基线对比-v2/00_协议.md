# 基线对比 v2 协议（方向 21 `baseline-comparison-v2`）

- 日期：2026-09-28
- 分支：`research/baseline-comparison-v2-protocol`（自 `main@ce88f2c`）
- 性质：**论文支撑方向（非创新点）**。本协议只写规则，不含实现。
- 一句话：**只补一个真实缺口——基线表里没有任何 Transformer 族模型（Informer/TST）；全部基线只用中心站单站点数据。**

## 0. 前身与教训（为什么是 v2，而不是复活方向 20）

方向 20 `baseline-comparison` 已于 2026-09-28 结项为 **FAILED**（索引 `ce88f2c`），四类公平对照均不利：

| 对照 | 结果 |
|---|---|
| 同信息集多站点 GRU（18 站、21k 全训练） | 我们 **−2.82%**（11/48 更优） |
| 同可训练预算单站点 GRU（≈5k） | 我们 **−1.38%**（验证集口径）/ **−3.44%**（测试集口径） |
| 端到端同主干同自由度 | 我们 **−23.47%**（中位 −0.96%，128/384 更优） |
| 冻结主干内的机制增益 | **+1.43%**（唯一为正，98/111） |

**本协议的目标不是翻案。** 它只解决两件事：

1. **补齐缺口**：仓库里 `Informer_model.py` 从未在当前协议下运行过（唯一一次是 2026-08 旧流程，
   见 `docs/ST-PatchTST指标记录.md:787`，多通道 12 输出、旧划分，**不可比**）。
2. **兑现两次被推迟的承诺**：
   - `docs/预测步覆盖扩展/00_协议.md:4`：「其他模型家族（**Informer**/CT/经典基线）的对比放在本轮之后」
   - `docs/预测步覆盖扩展/01_结果与解读.md:160`：「…按用户指示放在覆盖扩展之后」
   - 方向 20 协议 D3：「纳入 `Informer_model.py` / CT-PatchTST → **暂不纳入** → 写入 future work」

以 PatchTST 为主干的论文，几乎必然被审稿人追问 **Informer/Transformer 族基线**。本方向即为此而立。

## 2. 信息集与公平规则（强制，违反即结果作废）

1. **所有基线只用中心站单站点数据**（输入通道 = 1；中心站在通道顺序中的索引必须由实现断言，
   北京 1013 的索引为 9，须在测试中按站点 ID 解析而非硬编码）。
2. 我们一侧的模型使用中心站＋邻站（18 站），**信息集不同**——所有表格必须显式标注此差异。
3. **容量对齐按「可训练参数量」**，不按总参数量。每臂必须登记
   `trainable_parameter_count` / `total_parameter_count`，并由独立代码路径重构核对。
4. **禁止用测试集挑选对手或主干**。一切选择只用验证集。
   结论必须同时给出两组数字并标明口径：
   - **验证集口径**（双方都按验证损失选，公平）
   - **测试集口径**（双方都按测试表现选，上界/乐观）
5. 必须报告每个家族**验证损失与测试 RMSE 的秩相关**（方向 20 实测 **−0.20**；
   若为负或近零，必须在结论里说明「按验证集选对手会偏离测试最优」）。
6. 所有配对统计只使用**共同子集**：同一 `(history, horizon, seed)` 上两侧都 `completed`。
   禁止用不同子集的平均值互相比较（方向 20 第一版即踩此坑）。

## 3. 数据与训练配方（与既有主实验逐项一致）

| 项 | 规定 |
|---|---|
| 数据集 | `run_beijing_leakfree_coverage.prepare_datasets_leakfree`（无泄漏：训练段筛站），北京中心站 1013 |
| 划分 | 时间序 70% / 10% / 20%（训练/验证/测试），与无泄漏版本一致 |
| 种子 | 头条配置（24→1、168→6）`2047–2051`；其余配置 `2047–2049`；**不得新增种子** |
| 优化 | AdamW，`lr=1e-3`，`wd=1e-4`；`ReduceLROnPlateau(0.5, patience=3)`；MSELoss；梯度裁剪 1.0 |
| 轮次 | `L≤48` → epochs 40 / patience 8 / batch 256；`L>48` → epochs 30 / patience 6 / batch 512 |
| 早停 | 按**验证损失**；取该轮权重作为最终模型 |
| 评估 | 测试段**只评估一次**；反标准化到 µg/m³ 后算 RMSE/MAE |
| 训练路径 | **所有臂（含 Informer）必须走与 GRU/LSTM 相同的 tsai `Learner` 路径**（同 dls、同 preproc/exp pipeline）。Informer 以「tsai 兼容模型类」接入（输入 `[B,C,L]` → 输出 `[B,C_out,pred_len]`，`LTSF_Informer` 已满足该约定），**不得另写一套训练循环**。 |
| 传统基线 | 沿用已归档实现（不重跑）；其确定性臂按 `deterministic` 标记，不参与按种子的配对 |

## 4. 臂与容量网格

### 4.1 Informer（新增，主）
- 固定：`factor=5`、`attn="prob"`、`distil=True`、`dropout=0.1`、`attn_dropout=0.1`、`d_ff=2×d_model`、`d_layers=1`
- 网格：`d_model ∈ {8, 16, 32}` × `e_layers ∈ {1, 2}`，`n_heads = 1`（须整除 `d_model`），
  `label_len = min(48, L//2)`（与实现默认一致）
- 预期可训练参数区间（实现后以实测登记为准）：`d_model=8` ≈ 1–2k；`16` ≈ 5–8k；`32` ≈ 20–30k

### 4.2 TST（新增，次）
- 网格：`d_model ∈ {8, 16, 32}` × `n_layers ∈ {1, 2}`，`n_heads = 1`

### 4.3 复用臂（不重跑）
- 单站点 GRU/LSTM 容量曲线：`hidden ∈ {8,16,32,40,48,64}`（≈220 → 12.8k 可训练）
- 传统基线：persistence / 日周期 / 气候均值 / AR / Ridge / 线性空间回归

### 4.4 我们一侧
- **O-locked（主表唯一）**：方向 0 锁定结构（Top-5 门控＋站点身份偏置＋退化初始化＋**冻结主干**），
  逐配置数字取自 main（`tables/beijing_leakfree_coverage/H1–H9`）。
- **O-upgraded（仅附注，不进主表）**：主干升级变体（归档 `backbone-upgrade-f0d2bd3`）。
  引用时必须标注「未锁定变体、来自已 FAILED 分支」。

## 7. 失败处理（统一，落盘不中断）

| 情况 | 处理 |
|---|---|
| OOM | 登记 `infeasible_oom`，不重试同配置 |
| 非有限损失/梯度 | `lr/10` 重试一次；仍非有限 → 登记 `nonfinite` |
| 输出非有限（测试前向 Inf/NaN） | 登记 `nonfinite_prediction`；**不得**按 `completed` 写盘 |
| 设备级 hang（GPU reset 等） | 事先在协议中登记排除的配置（预注册），事后不得追加排除 |
| 所有失败 | 计数入报告，**排除**于配对统计，但不从合规表中消失 |

## 8. 合规自检（每次正式运行后必须全绿，逐项落盘）

1. 运行身份数 = 预期数（逐臂 × 逐 (配置,种子)）
2. 所有运行状态为终态（`completed` / 已登记失败类别）
3. **基线输入通道 = 1**；中心站通道索引由站点 ID 解析并断言
4. 我们一侧输入通道 = 18
5. `completed` 行的指标全为有限值
6. 参数量独立重构一致（`trainable` / `total`）
7. 从保存的预测**独立复算** RMSE，与落盘指标一致（相对差 < 1e-9）
8. `best_valid_loss` 与训练日志逐位一致
9. 选择只用验证集、测试段只评估一次（`selection_split=valid`、`evaluation_split=test`、`test_evaluation_count=1`）
10. **语义等价门**：Informer/TST 包装器与既有 runner 在相同种子、相同权重初始化下的首批损失一致（容差 1e-6 相对）；
    另做「同随机种子两次运行位级可复现」检查
