## 0. 前身与教训（为什么是 v2，而不是复活方向 20）

方向 20 `baseline-comparison` 已于 2026-09-28 结项为 **FAILED**（索引 `ce88f2c`），四类公平对照均不利：

| 对照 | 结果 |
|---|---|
| 同信息集多站点 GRU（18 站、21k 全训练） | 我们 **−2.82%**（11/48 更优） |
| 同可训练预算单站点 GRU（≈5k） | 我们 **−1.38%**（验证集口径）/ **−3.44%**（测试集口径） |
| 端到端同主干同自由度 | 我们 **−23.47%**（中位 −0.96%，128/384 更优） |
| 冻结主干内的机制增益 | **+1.43%**（唯一为正，98/111） |

**本协议的目标不是翻案。** 它只解决两件事：

1. **补齐缺口**：仓库里 `Informer_model.py` 从未在当前协议下运行过（唯一一次是 2026-08 旧流程，
   见 `docs/ST-PatchTST指标记录.md:787`，多通道 12 输出、旧划分，**不可比**）。
2. **兑现两次被推迟的承诺**：
   - `docs/预测步覆盖扩展/00_协议.md:4`：「其他模型家族（**Informer**/CT/经典基线）的对比放在本轮之后」
   - `docs/预测步覆盖扩展/01_结果与解读.md:160`：「…按用户指示放在覆盖扩展之后」
   - 方向 20 协议 D3：「纳入 `Informer_model.py` / CT-PatchTST → **暂不纳入** → 写入 future work」

以 PatchTST 为主干的论文，几乎必然被审稿人追问 **Informer/Transformer 族基线**。本方向即为此而立。

## 2. 信息集与公平规则（强制，违反即结果作废）

1. **所有基线只用中心站单站点数据**（输入通道 = 1；中心站在通道顺序中的索引必须由实现断言，
   北京 1013 的索引为 9，须在测试中按站点 ID 解析而非硬编码）。
2. 我们一侧的模型使用中心站＋邻站（18 站），**信息集不同**——所有表格必须显式标注此差异。
3. **容量对齐按「可训练参数量」**，不按总参数量。每臂必须登记
   `trainable_parameter_count` / `total_parameter_count`，并由独立代码路径重构核对。
4. **禁止用测试集挑选对手或主干**。一切选择只用验证集。
   结论必须同时给出两组数字并标明口径：
   - **验证集口径**（双方都按验证损失选，公平）
   - **测试集口径**（双方都按测试表现选，上界/乐观）
5. 必须报告每个家族**验证损失与测试 RMSE 的秩相关**（方向 20 实测 **−0.20**；
   若为负或近零，必须在结论里说明「按验证集选对手会偏离测试最优」）。
6. 所有配对统计只使用**共同子集**：同一 `(history, horizon, seed)` 上两侧都 `completed`。
   禁止用不同子集的平均值互相比较（方向 20 第一版即踩此坑）。

## 5. 指标、统计与报告

### 5.1 主表
每个基线家族（Informer / TST / GRU-LSTM / 传统）给出：
- 逐配置 RMSE（µg/m³）与池平均；

- 分层：按预测步 H（1/3/6/12/24）、按历史长度 L（24/48/72/168）。

### 5.2 逐 lead（步内）分析 —— 必做，零额外训练

**定义**：H 步任务的每个输出步单独算指标。`y` 形状 `[样本, 1, H]` 的最后一维下标 k 即 lead
（lead 1 = t+1，lead k = t+k）。

```python
per_lead_rmse = np.sqrt(np.mean((prediction - target) ** 2, axis=0))   # 长度 = H
```

（与仓库既有实现一致：`make_frequency_paper_artifacts.py:361`；模板复用
`figures/frequency_legacy/FF6_per_lead_168h6h.*`、`figures/round14/F2_per_lead.*`、
`tables/round14/T3_per_lead.*`）

| 项 | 规定 |
|---|---|
| 覆盖 | **H ∈ {6, 12, 24}** 的全部配置（H=1 只有 lead 1，退化为总体值，不画） |
| 每臂输出 | 逐 lead RMSE（µg/m³）曲线，按种子画细线 + 均值粗线 |
| 对照输出 | 相对 O-locked 的**逐 lead 配对差**（同 (配置, 种子, lead)）；给出"哪几步赢/输" |
| 必报数字 | 每个 lead 的平均相对变化；胜负 lead 计数（如 24 步里赢 6 步） |
| 禁止 | 用逐 lead 结果反向挑选臂或配置（仍按验证集选择规则） |

**目的**：把"总体平均"掩盖的结构暴露出来——已有证据显示我们的空间适配在长 lead 上几乎失效
（168→24：空间头 `best_epoch=1~2`、残差比仅 3%），逐 lead 曲线是验证该现象的直接证据。

## 7. 失败处理（统一，落盘不中断）

| 情况 | 处理 |
|---|---|
| OOM | 登记 `infeasible_oom`，不重试同配置 |
| 非有限损失/梯度 | `lr/10` 重试一次；仍非有限 → 登记 `nonfinite` |
| 输出非有限（测试前向 Inf/NaN） | 登记 `nonfinite_prediction`；**不得**按 `completed` 写盘 |
| 设备级 hang（GPU reset 等） | 事先在协议中登记排除的配置（预注册），事后不得追加排除 |
| 所有失败 | 计数入报告，**排除**于配对统计，但不从合规表中消失 |

## 8. 合规自检（每次正式运行后必须全绿，逐项落盘）

1. 运行身份数 = 预期数（逐臂 × 逐 (配置,种子)）
2. 所有运行状态为终态（`completed` / 已登记失败类别）
3. **基线输入通道 = 1**；中心站通道索引由站点 ID 解析并断言
4. 我们一侧输入通道 = 18
5. `completed` 行的指标全为有限值
6. 参数量独立重构一致（`trainable` / `total`）
7. 从保存的预测**独立复算** RMSE，与落盘指标一致（相对差 < 1e-9）
8. `best_valid_loss` 与训练日志逐位一致
9. 选择只用验证集、测试段只评估一次（`selection_split=valid`、`evaluation_split=test`、`test_evaluation_count=1`）
10. **语义等价门（两道）**：
    (a) **骨架复现门**：新 runner 的 `gru_h16` 臂在单个 (配置, 种子) 上必须**位级复现**归档
    `trainable_matched` 的对应记录（RMSE 与 `best_valid_loss` 相对差 < 1e-9）——证明只是搬了骨架、没改语义；
    (b) **包装门**：Informer/TST 包装器的输出形状 `[B,1,H]`、输入通道 = 1、参数量与 §4 登记一致；
    同种子两次运行可复现（位级）

### 11.3 执行顺序

1. 骨架移植（自 `-failed` 分支）＋包装＋测试（含 §8 十项门）→ 单配置冒烟（24→1、168→6、seed 2047，全部 8 臂）

4. 结论回写索引（**main 变更需单独批准**）

### 11.4 预算硬边界

- 正式矩阵运行数**不得超过 512**；可选 `informer_d48_e1` 追加臂须单独批准（+64 次）。
- 统一环境：`OMP_NUM_THREADS=1`、`MKL_NUM_THREADS=1`、`MPLBACKEND=Agg`、`ulimit -c 0`、
  `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`、`HSA_ENABLE_SDMA=0`、`unset DISPLAY WAYLAND_DISPLAY`。
