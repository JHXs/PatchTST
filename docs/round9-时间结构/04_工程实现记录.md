# 第 9 轮 CCSPRF 纯合成 L0 工程实现记录

日期：2026-09-10（Asia/Shanghai）。本记录更新于补充协议 `e063b89` 之后；正式种子仍未运行。

## 交付实现

- `ccsprf_l0.py` 直接包装 `tsai.models.PatchTST.PatchTST`，输入 `[B,L]` 显式变为 `[B,1,L]`，输出 `[B,1,H]` 还原为 `[B,H]`。固定主干参数为 `c_in=c_out=1`、`n_layers=3`、`n_heads=4`、`d_model=16`、`d_ff=128`、`dropout=0.2`、`attn_dropout=0`、`patch_len=4`、`stride=2`、`padding_patch=True`。
- 四臂均先按同一种子构造同一 PatchTST 主干，再构造 EMB；初始主干 `state_dict` hash 记录在每个 artifact 和每个 seed/task/condition 审计表中。EMB 只增加 `(24+7)×4=124` 参数。构造后、loader 与训练前统一重置 `training_rng_seed=seed+1000003`，因此 EMB 的额外初始化不会改变四臂 dropout/loader RNG 轨迹；该 seed 同步落入 manifest、progress 和 artifact。
- DGP 严格使用 8736 小时点、Unix epoch 起点、固定非零 calendar-on 效应、calendar-off 零效应、`default_rng(seed)`/PCG64、一次完整 `normal`、初始动态残差 0 及固定 cut 规则。raw synthetic 序列以 float64 保存，避免 scale 复算误差。
- calendar LOO 同时排除自身分组值和全局均值：`mu0^-t=(N*mu0-y_t)/(N-1)`；`n_c=1` 时直接回退到 `mu0^-t`。`CCSPRF-global` 不使用 tau 收缩；calendar 先验固定 `tau=50`。
- 预测 artifact 保存 scaled/raw target、prior、prior-only、residual、逐预测步目标时间和 SHA-256 manifest；仅 EMB 额外保存最终 `emb_hour_weight[24,4]` 与 `emb_weekday_weight[7,4]`，摘要器按 target timestamp 独立用 mean(concat(hour, weekday)) 重建 EMB prior；非 EMB 禁止这两个字段。训练 LOO checksum、测试冻结先验和预测重建均可复核。
- row、audit、artifact sidecar 均显式记录 `tau_applied`：只有 CCSPRF 为 `true` 且 `tau=50`，BASE/EMB/CCSPRF-global 为 `false` 且 `tau=null`；canonical 仍记录固定 CCSPRF tau=50。
- `run_ccsprf_l0.py --formal` 固定 480 个 key，默认输出为 `experiments/results/round9/l0_formal`；初次运行执行脚本所在 worktree 的 Git root clean-tree 与输出目录不存在门；canonical manifest/progress 在首个训练前原子写入，每个 key 完成后原子更新。`--resume` 复核 source commit 与源码树（仅允许 output_dir 自身 dirty）、完整配置、DGP、key hash，并对 completed key 只读验证 dataset/prior/artifact/sidecar/training log/raw row；progress 落后时最多只 reconciliation canonical 前缀后的一个完整 key，仅原子补记 progress、不重训；缺失、部分残留或篡改拒绝且不补写、不覆盖。
- canonical manifest 还保存包含 `source_commit`、配置和 expected keys 的 payload SHA-256。`summarize_ccsprf_l0.py` 不导入 runner、先验函数、指标函数或 artifact verifier；它独立枚举 formal 480 笛卡尔积，重建 DGP、split、scale、唯一目标时间戳、calendar/global LOO checksum、测试先验、target 对齐、初始主干 hash、EMB 参数增量、prediction reconstruction 和全部 gate，且独立复核 manifest/progress payload hash。摘要成功后原子写 `strict_release_status.json`，只明确 `PASS` 或 `STOP`；`raw_metrics.csv` 不一致报告 `ENGINEERING_FAILURE`。
