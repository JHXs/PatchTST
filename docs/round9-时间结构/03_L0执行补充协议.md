# 第 9 轮 CCSPRF 纯合成 L0 执行补充协议

日期：2026-09-10。状态：正式种子尚未运行；本补充在任何正式性能结果产生前冻结，优先于 `01_候选机制.md` 中未定量或表述不完整的执行细节。

## 1. 冻结 DGP

每个条件固定生成 `8736` 个连续小时点，起点为 Unix epoch `1970-01-01 00:00:00`，按原始时间点 `70%/10%/20%` 切分，所有窗口目标时间戳跨 split 不重叠。固定：

- `mu=10.0`、`rho=0.60`、`noise_std=0.80`；初始动态残差固定为 0；
- `epsilon_t` 为独立同分布 `Normal(0, 0.80^2)`；固定使用 `numpy.random.default_rng(seed)` 的 PCG64 生成器，在递推前以一次 `normal(0, noise_std, size=num_points)` 调用生成完整噪声数组，之后不得再调用该 RNG；
- calendar-on 的小时原始效应固定为 `[-1.10,-1.25,-1.30,-1.15,-0.80,-0.20,0.55,1.00,1.25,1.10,0.80,0.45,0.15,-0.05,-0.20,-0.05,0.25,0.70,1.10,0.95,0.45,-0.10,-0.60,-0.90]`，使用前减去其均值；
- 星期原始效应固定为 `[0.95,0.40,-0.25,-0.65,-0.45,0.15,0.85]`，使用前减去其均值；
- calendar-off 只令上述两组效应为零；同种子、同任务复用完全相同的噪声数组；
- 时间戳使用 `numpy.int64` 纳秒；切点固定为 `train_cut=int(num_points*0.70)`、`valid_cut=int(num_points*0.80)`，即 Python 向零截断（此处等同 floor）；窗口仅按目标时间戳所属区间划分；
- `tau=50`，不得使用 fixture 或正式结果改动。

已运行的非正式 fixture 仅使用种子 `991103`，其作用是工程通路测试，不构成筛选资源；正式种子 `20260939..20260968` 尚未运行。

## 2. 精确主干与四臂公平性

L0 必须直接实例化当前项目 `ST_PatchTST_model.py` 所用的 `tsai.models.PatchTST.PatchTST`，不得以自定义 Transformer surrogate 替代。固定：`c_in=c_out=1`、`n_layers=3`、`n_heads=4`、`d_model=16`、`d_ff=128`、`dropout=0.2`、`attn_dropout=0.0`、`patch_len=4`、`stride=2`、`padding_patch=True`；`seq_len/pred_dim` 仅随 `24→1`、`168→6` 改变。外部训练目标标准化、AdamW、学习率、权重衰减、epoch、patience、batch size、最佳验证 MSE 规则在四臂间完全相同。

每个 `seed×task×condition` 中，四臂主干必须由同一种子以相同顺序初始化；EMB 的 124 个新增参数在主干构造后初始化，不能扰动主干初始权重。保存或散列主干初始 `state_dict`，独立摘要必须验证四臂一致。

## 3. 全局中心化对照的精确公式

`CCSPRF-global` 不使用 `tau`。设训练唯一目标时间戳集合大小为 `N`、标准化目标全局均值为 `mu0`：

- 训练唯一时间戳 `t` 使用 `mu0^{-t}=(N*mu0-y_t)/(N-1)`；
- 验证/测试统一使用完整训练集合的 `mu0`；
- 禁止再把 `mu0^{-t}` 向 `mu0` 做任何收缩。

calendar 先验继续按 `01` 的唯一时间戳 LOO 和 `tau=50` 执行，但修正其全局收缩基准：对训练唯一时间戳 `t`，必须同时排除分组均值和全局均值中的自身目标，

`mu0^{-t}=(N*mu0-y_t)/(N-1)`，

`tilde_mu_c^{-t}=w_c^{-t}*bar_y_c^{-t}+(1-w_c^{-t})*mu0^{-t}`，其中 `w_c^{-t}=(n_c-1)/(n_c-1+tau)`。当 `n_c=1` 时第一项按 0 处理且先验等于 `mu0^{-t}`。若 `N=1`，该实验配置直接 `ENGINEERING_FAILURE`，不得使用含自身的 fallback。验证/测试仍使用完整训练集合的 `mu0` 和 calendar 表。

## 4. 补充强对照和动态完整性门

所有比例均按种子配对后取 30 种子的中位数，并用 `01` 固定的 RNG `20260969`、`B=10000` 按种子 bootstrap。

### 4.1 EMB 强对照

对每个任务定义：

`Delta_emb = median_s(1 - RMSE_s(CCSPRF) / RMSE_s(EMB))`。

放行还要求 `Delta_emb >= 0`，且其 95% 配对 bootstrap 下界 `> -0.02`。这表示 0 参数 CCSPRF 的点估计不得差于普通逐步日历 embedding，并排除超过 2% 的实质劣效。失败即 STOP，不能用 BASE 收益替代。

### 4.2 残差头不是空壳

对 CCSPRF 定义 `prior-only` 预测为冻结日历先验 `p`，以及：

`Delta_residual = median_s(1 - RMSE_s(p + residual_head) / RMSE_s(p))`。

两个任务均要求 `Delta_residual >= 0.05` 且 30/30 种子均严格大于 0；否则视为收益仅来自先验或残差头破坏动态，STOP。这是主代理在任何正式结果产生前有意加入、且严于原 H3 的严格门，不能在结果产生后放宽。

### 4.3 168→6 后段不恶化

仅对 `168→6`，将预测步 4–6 合并计算 `RMSE_late`，定义：

`Delta_late = median_s(1 - RMSE_late,s(CCSPRF) / RMSE_late,s(BASE))`。

要求 `Delta_late >= 0` 且 bootstrap 下界 `> -0.02`；否则视为多步后段存在不可接受退化，STOP。

以上三项与 `01` 已冻结的主效应、`Delta_calendar`、calendar-off 三类门为并集，任一失败均为性能 STOP。

## 5. 独立复算与完整性

正式输出必须恰好覆盖 `30 seeds × 2 tasks × 2 conditions × 4 arms = 480` 个唯一 artifact。摘要脚本必须从实际文件枚举该笛卡尔积；缺失、重复、额外、非法路径、identity 不一致或只在 manifest 声称完成，均为 `ENGINEERING_FAILURE`，不得进入性能门。

摘要脚本不得复用 runner 的先验、指标或 artifact 校验实现。它必须用独立代码路径完成：

1. 从保存的原始序列、时间戳和冻结 metadata 重建 split、标准化统计、唯一训练目标集合；
2. 逐元素核对 artifact 的 `target_scaled`、`target_raw` 与数据集目标；
3. 独立复算 global/calendar 的训练 LOO checksum 和测试先验；
4. 独立核对 `prediction=prior+residual`、反标准化、shape、有限值、逐步及总体指标；
5. 验证四臂主干初始 hash 相同、EMB 增量参数为 124；
6. 独立计算全部旧门和本补充三项门。

runner 的 `raw_metrics.csv` 仅作运行日志；若与独立复算不一致，以独立复算为准并记录工程失败。
