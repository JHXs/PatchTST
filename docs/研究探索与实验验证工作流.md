# 研究探索与实验验证工作流

## 1. 目的

本工作流用于后续模型改进研究，将“理论可行性探索”“实现与消融”“独立确认”分开，避免在理论尚未明确时过早修改正式模型，也避免根据确认结果反复调参。

Git 分支和 Herdr worktree 提供代码与资料的物理隔离，但不能代替实验设计上的独立性。数据边界、候选选择、随机种子、指标和放行规则仍需预先固定。

## 2. 推荐分支结构

```text
main
├── research/<idea>-theory
├── experiment/<idea>-ablation
└── experiment/<idea>-confirmation
```

三个分支的职责如下：

| 分支 | 起点 | 用途 | 禁止事项 |
|---|---|---|---|
| `research/<idea>-theory` | `main` | 文献、开源实现、理论推导、可行性和风险分析 | 不开展正式模型实验，不根据测试集形成方案 |
| `experiment/<idea>-ablation` | 最新稳定 `main` | 实现候选、单元测试、冒烟测试、训练集/验证集选择和消融 | 不把探索性测试结果包装成独立确认 |
| `experiment/<idea>-confirmation` | 消融分支中选定的固定 commit | 用冻结结构、配置和新种子进行最终确认 | 不因确认结果修改结构或超参数后重复使用同一确认数据 |

`<idea>` 使用简短、稳定的英文 kebab-case 名称，例如 `adaptive-lag-fusion`。理论分支使用 `research/`，代码实验和正式确认使用 `experiment/`。

## 3. 阶段一：理论探索

### 3.1 创建

理论探索分支直接从 `main` 创建：

```bash
git worktree add \
  -b research/<idea>-theory \
  ~/.herdr/worktrees/PatchTST/research-<idea>-theory \
  main
```

随后可让 Herdr workspace 指向该 worktree。一个本地分支同一时间只能被一个 worktree 检出。

首次推送时设置 upstream：

```bash
git -C ~/.herdr/worktrees/PatchTST/research-<idea>-theory \
  push -u origin research/<idea>-theory
```

### 3.2 应形成的产物

至少记录：

1. 研究问题及其与现有 ST-PatchTST 的关系；
2. 代表性论文、发布日期、代码仓库和许可证；
3. 已有方法的输入、输出、因果边界和计算成本；
4. 候选改进的机制假设，而不是只描述模块拼接；
5. 预期可观测证据、主要风险和否证条件；
6. 数据泄漏检查；
7. 最小可行实现和逐组件消融顺序；
8. 进入代码实验前的明确放行结论。

论文和开源代码只作为证据来源。应保存来源链接和访问日期，区分论文原始结论、代码实际行为和本项目推断。

### 3.3 阶段门

理论探索结束时只能做出以下两类决定：

- **放行**：形成固定的最小方案、基线、消融矩阵、主指标和停止规则，再进入实验分支；
- **止损**：记录不可行原因和已排除方案，推送并归档分支，不创建对应实验分支。

理论止损也是有效研究结果，不应删除其分支或提交。

## 4. 阶段二：实现与消融

### 4.1 从 `main` 独立创建

理论分支主要包含调研资料，因此实验分支应重新从最新稳定 `main` 创建，而不是默认继承整个理论分支：

```bash
git worktree add \
  -b experiment/<idea>-ablation \
  ~/.herdr/worktrees/PatchTST/experiment-<idea>-ablation \
  main
```

如实验必须携带最终理论方案，可采用以下任一种方式：

1. 将最终方案人工整理为实验分支中的简洁协议；
2. 将理论分支的最终方案整理成单独 commit，再用 `git cherry-pick <commit>` 复制该提交。

不要为了获得一份文档而合并整个理论探索分支。

### 4.2 实验范围

消融分支允许：

- 实现候选模型；
- 增加形状、梯度、退化不变性和组件独立性测试；
- 运行 CPU/GPU 冒烟测试；
- 使用训练集和验证集筛选结构及超参数；
- 记录失败候选、运行日志和选择依据。

必须保持对照公平：数据、划分、种子、主干、初始化、优化器、训练流程和最佳模型规则应尽可能一致。测试集不得参与候选选择。

### 4.3 冻结候选

准备进入确认前，应选定一个明确 commit，并记录：

- commit hash；
- 固定模型结构和默认参数；
- 数据版本与划分；
- 选择阶段已经使用的种子；
- 确认阶段尚未使用的新种子或新数据；
- 主次指标、统计方法和放行阈值；
- 失败后的停止规则。

## 5. 阶段三：独立确认

确认分支从消融阶段选定的固定 commit 创建：

```bash
git worktree add \
  -b experiment/<idea>-confirmation \
  ~/.herdr/worktrees/PatchTST/experiment-<idea>-confirmation \
  <selected-commit>
```

这样确认分支完整拥有已选定实现，而消融分支之后的新提交不会自动进入确认分支。

确认阶段只允许：

- 执行预先固定的命令；
- 使用预先保留的新种子、新中心站或新城市；
- 修复阻止实验运行的纯工程错误；
- 汇总指标、复算统计并撰写边界明确的结论。

如果发生工程修复，应记录修复内容，并判断其是否可能改变模型或实验结果；可能改变结果的修复需要重新冻结协议。不得查看确认结果后调整模型，再继续把同一批数据称为“独立确认”。

确认通过后才考虑合并到 `main`。确认失败时，将结果降级为探索证据并归档；若提出新候选，应返回新的消融周期，并使用未被消费的新确认资源。

## 6. Worktree 与分支归档

### 6.1 推送和检查

结束一个阶段前执行：

```bash
git status --short --branch
git push -u origin <branch>   # 首次推送
git branch -vv
git worktree list
```

确保工作区干净，且本地分支具有对应 upstream。

### 6.2 移除 worktree

先关闭对应 Herdr workspace 或其中的进程，再执行：

```bash
git worktree remove <worktree-path>
```

该命令只删除检出的工作目录，不删除本地分支、commit 或远程分支。以后可以恢复：

```bash
git worktree add <worktree-path> <existing-branch>
```

除非明确决定永久丢弃，不要对归档研究分支执行 `git branch -D` 或删除远程分支。失败实验应保留提交、协议和结论，以避免后续重复走同一条无效路线。

## 7. 决策速查

```text
提出新想法
  ↓
research/<idea>-theory：只做理论与资料探索
  ├─ 不可行 → 记录止损 → 推送 → 移除worktree并保留分支
  └─ 可行   → 固定最小方案与实验协议
                ↓
experiment/<idea>-ablation：实现、验证集选择、逐组件消融
  ├─ 不成立 → 记录负结果 → 归档
  └─ 候选成立 → 冻结selected commit与确认规则
                     ↓
experiment/<idea>-confirmation：新种子/新数据独立确认
  ├─ 失败 → 降级为探索证据，不复用确认资源调参
  └─ 通过 → 更新报告，审查后合并main
```

## 8. 最低记录要求

每个研究方向无论成功或失败，至少应能回答：

- 为什么提出该方向；
- 查阅了哪些论文和实现；
- 理论机制和可否证假设是什么；
- 使用了哪些数据、种子和指标；
- 哪些信息用于选择，哪些保留用于确认；
- 最终为何放行或止损；
- 对应分支、固定 commit、命令和结果目录在哪里。
