# Round 11 CF-CV-CS fixture 工程实现记录

日期：2026-09-10。范围：仅非正式 synthetic fixture；不包含真实站点数据、checkpoint、旧结果或正式 L0。

本实现新增四个入口文件：

- `cf_cv_smearing_fixture.py`：单序列 DGP、窗口、时间切分、train-inner/5 个 forward OOF 索引、实际 tsai PatchTST 单通道适配、HPC、线性 conditional smoother 与控制变量算子。
- `run_round11_cf_cv_fixture.py`：registered fixture 固定使用 `4001,4002,4003`，每个 seed/task 产生 `raw_full + 5 log_oof + log_full = 7` 次拟合，总计 42 次；其语义固定为 `registered_fixture=true, formal_l0=false, formal=false, non_formal=true`。`--smoke` 只允许单 seed、必须写入 `_smoke` 目录，并额外标记 `smoke=true`；默认 smoke 使用 `N=2048,burn-in=256,warmup=0.35`，registered 42-fit 模式固定 `N=4096,burn-in=512,warmup=0.20`，两者不可混入门控结果。
- `summarize_round11_cf_cv_fixture.py`：从 seed、DGP、切分和预测数组重建标签、算子与 raw 指标，不读取 runner 写入的指标作为真值；输出隔离在 `verification/summary.json` 和 `verification/manifest.json`，不修改 runner 的 `manifest.json`。
- `test_round11_cf_cv_fixture.py`：覆盖标签唯一性、非负边界、形状、purge/泄漏、42 键契约、矩形算子、旧方阵接口拒绝、恒等式、tamper 和恢复窗口。

## 冻结实现边界

05 覆盖 03 的模型接口：输入严格为 `X=[B,1,L]`，目标严格为 `y=[B,1,H]`；PatchTST 配置为两层、两头、`d_model=16`、`d_ff=64`、`patch_len=8`、`stride=4`。C 只由 lead、log 预测、历史均值/标准差、当前值和历史 slope 构成，不加入 calendar 或 target encoding。

每个 DGP replication 只在绝对时间轴上生成一次 `(Z,Y)`，H1/H6 仅从这两个唯一数组切窗。切窗器保留绝对 `target_timestamps`，在生成时执行跨 lead 逐点相等断言与 `Y>=0` 断言。H1/H6 的窗口属于同一时间序列，目标窗口跨越 split 边界时丢弃。

OOF 使用 warm-up 加五个连续 query blocks。每个 m-OOF 模型只使用 `target_timestamp <= query_min-purge` 的 prefix；inner valid 也只从 train-inner blocked validation 产生早停决定。outer valid/test 只保留为最终评价数据。权重按 05 覆盖规则为每 lead 的单位权重。

`B` 和 `H_E` 均是按固定训练记录列顺序的稀疏行线性算子。为使大 H6 fixture 保持可复现的有限内存，Gaussian local-linear smoother 预注册固定最多 128 个最近、且 purge 合法的 fit 行；该支持截断不允许查询行回填。`B` 在统一训练 residual 空间中工作，`H_E` 的形状为 `[evaluation_rows, training_records]`，没有 `H²` 或 `kappa` 接口；对矩形算子自乘会明确抛错。removal 与 strongest existing conditional smearing 共享同一 factor 数组。候选只改变 `u` 为 `u-lambda*v`，并用 float64 以 `rtol=1e-10, atol=1e-12` 验证逐点恒等式。

artifact 采用同目录临时文件加 `os.replace` 原子写入；manifest 保存每个 JSON/NPZ 的 SHA-256，启动恢复时先验真并拒绝 tamper。任务产物写完但 progress 尚未提交的崩溃窗口可由有效 JSON/NPZ 对恢复。正式目录已存在时拒绝覆盖；smoke 目录明确标注不得用于门。metadata 保存 seed 集合、历史 seed 清单、fit keys、commit/branch/clean-tree 绑定、实际耗时和配置。

本记录不报告 fixture 性能、不授权 formal L0，也不授权真实空气质量数据实验。实现后只允许执行单测与极小 smoke；不得运行 `3 seeds × 42` 训练作为本次交付步骤。

## 2026-09-10 审计修复记录

依据 09 前向样本空间更正和 12 号工程修复授权，当前实现已补齐以下边界；10–12 号审计文档原样保留。

- `M` 保存全部合法 m-OOF 记录；`S` 只保留当时已有至少两个同 lead、严格更早且满足 `purge=L+H+1` 的 M 前缀。第一批 M 只作为后续 B 的列空间，不进入 S、最终 H 或最终 `u/v`；第一批合法 S 可进入后续 H fit 池。每个 B 行支持同 lead、严格早、purge 合法的 M 列，并保存支持索引。
- raw full、log full 和五个 log OOF fit 各自用自己的 `inner_fit` 拟合输入 scaler 与逐 lead target scaler；预测先逆 target scaler。条件 C 始终以 raw 值保存，B 与每个 H row 的 scaler 只由该行合法 fit prefix 拟合；最终 valid/test H 只使用训练期 S。S-OOF 只使用查询块之前的 S，并在自己的 prefix 上中心化和估计 lambda。
- bandwidth 固定为 `1.0`，support 固定上限 `128`，距离使用 stable sort；不执行伪选择。H、B 均为明确矩形算子，旧 `H²/kappa` 接口继续拒绝。逐 lead 的 `vtilde`、lambda、方差、协方差、variance ratio、rho 与算子维度均保存，并逐点验证 `S_cv-S_rem=-lambda H_Ev`。
- additive raw 对照的 log 目标是有限的 `log1p(Y)`；homoskedastic 与 additive raw 只做生成、标签、正值、跨 lead 及 global/HPC 公式单测，不进行神经训练，也不进入主 fixture 门。
- 每个任务 sidecar 记录 schema、unit key、精确 7 个 fit key、fit/inner-valid 索引、scaler 和 NPZ SHA-256。runner 在接受未登记 crash-window pair 前先验证 sidecar、fit keys、NPZ hash 和必需 NPZ schema；实际篡改该窗口 pair 会拒绝恢复。artifact 使用原子写入。
- summarizer 独立从 seed、DGP、split 和 OOF plan 重建 M/C/B/S/H、逐 lead 控制变量、global/HPC、所有 raw prediction 公式和每个 task 的七个 fit key；它只信任 NPZ 保存的 neural base 输出，并检查 42-key 笛卡尔契约（smoke 则按实际单 seed 的 14 keys 检查）。registered fixture 的执行门仍保持固定 `4001,4002,4003`、`N=4096`、`burn-in=512`、主异方差 DGP、clean round11 branch 和新输出目录；这些证据不构成 formal L0。
- registered metadata/summary 的语义固定为 `registered_fixture=true, smoke=false, formal_l0=false, formal=false, non_formal=true`；只有 registered 模式应用 rho 门，状态为 `COMPLETE/STOP`。smoke 的语义固定为 `registered_fixture=false, smoke=true, formal_l0=false, formal=false, non_formal=true`，状态为 `SMOKE_COMPLETE`，`rho_gate_applied=false`，仅保存 `rho_diagnostic_stop` 而强制 `rho_stop=false`。runner 只接受异方差 DGP 训练，homoskedastic/additive raw 仅保留生成和公式单测。
- 注册模式固定 `4001..4003`、`N=4096`、`burn-in=512`、`warmup=0.20`、40 epochs、patience 8、`batch_size=None`；device 可显式绑定。配置保存 resolved 规则，resume 不得改变训练预算。历史 seed 黑名单保守覆盖 `2024..2061`、`3101..3150`、`20260939..20260968`。metadata 记录 `task_elapsed_seconds_sum`、本次 `invocation_wall_time_seconds`、累计 `wall_time`、`ru_maxrss`、preflight commit/branch/clean binding；sidecar 记录 `elapsed_seconds`。
- registered 首次运行要求 output 不存在且 output 外 source clean，初始 manifest 原子保存 preflight binding；resume 必须 HEAD/branch 匹配且 output 外无 dirty。rho STOP 不在 metadata 前抛错，而是完整写出 metadata、runner manifest 和 `strict_fixture_status.json` 后返回 `status=STOP`；smoke 不应用该门。summarizer 只写 verification 目录，重复运行保持 runner manifest 不变且 verification 字节稳定。

本修复阶段仍未运行正式 42-fit fixture，也不解读 smoke 指标；仅允许单测、编译和带 `_smoke` 后缀的极小单 seed 训练后独立完整性验真。
