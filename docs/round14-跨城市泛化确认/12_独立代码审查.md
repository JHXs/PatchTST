## 2. 必须修订项

### R1（阻断）：配置指纹不能证明本次数据支持和代码可复现

证据：`run_cross_city_generalization.py:480-490` 只对配置、站号、种子、臂、打开集合、
smoke、HEAD、device 计算指纹；Top-5、相关系数、边界、三段样本索引、缩放统计、确认时间戳和
块标签在 `run_cross_city_generalization.py:495-496` 才并入 metadata，均未进入指纹。
`run_cross_city_generalization.py:433-437` 还允许 commit 为 `UNKNOWN`；正式入口
`run_cross_city_generalization.py:573-620` 不拒绝 dirty/untracked 工作树。当前三个实现文件本身为
untracked，故 HEAD 不能标识实际执行代码。汇总器在
`summarize_cross_city_generalization.py:129-140` 仅复算同一个不完整 payload，不能补救。

替代写法：在 `prepare_shared_data` 后构造 `frozen_run_payload`，至少加入
`selected_top5`、排序后的相关系数、`bounds`、全部 `sample_indices`、means/stds、完整 C-confirm
时间轴及重建块标签；对该规范 JSON 计算 SHA-256。正式模式在任何数据访问和输出创建前要求：
HEAD 为 40 位 commit、目标实现文件均已被 HEAD 跟踪、`git status --porcelain` 为空，否则抛
`ProtocolViolation`。汇总器从 metadata 独立构造同一 payload 后复算指纹。

### R2（阻断）：汇总器没有独立验证时间戳、lead 和五块归属，G4 可被协调篡改

证据：runner 在 `run_cross_city_generalization.py:270-278` 生成块标签，并在
`run_cross_city_generalization.py:453-466` 与预测一起保存。汇总器只检查标签属于 1–5
（`summarize_cross_city_generalization.py:72-91`），随后使用同一保存标签复算 SSE；
`summarize_cross_city_generalization.py:96-99` 只要求两臂标签相同。它没有把 artifact 的
时间戳/lead 与 `run_metadata.json` 的 `confirm_scalar_timestamps_ns`、
`confirm_scalar_block_labels` 比较，也未从完整 C-confirm 时间轴独立重建五块。
因此同时改两臂标签并重算冗余 SSE 可通过校验，并改变
`summarize_cross_city_generalization.py:238-242,286-313` 的 G4。lead 也只检查 `>=1`
（`summarize_cross_city_generalization.py:79-80`），未检查 `<=H` 和序列结构。

替代写法：runner metadata 新增完整 `confirm_timestamps_ns`；汇总器按协议重新执行
`divmod(n, 5)`、余数前置，依据每个标量 `target_timestamp_ns` 重建标签，并逐元素断言保存标签
相等；同时断言 artifact 时间戳等于 metadata 的共享标量时间戳，lead 位于 `[1,H]`，且每个窗口
严格为 `1..H`、对应目标时间戳。G4 只能使用重建标签。

### R3（阻断）：工作单要求的“无 `bfill` 路径”没有被全仓库证明

证据：Round 14 runner 的实际填充辅助函数仅调用 `ffill`
（`run_cross_city_generalization.py:144-148`），三段也分别调用该辅助函数
（`run_cross_city_generalization.py:249-252`），本文件路径本身正确。但测试仅对 runner 单模块做
源码字符串检查（`test_cross_city_generalization.py:31-39`），不能证明全仓库或可达导入路径。
tracked `*.py` 的只返回文件名检索仍命中 `run_st_patchtst_ablation.py`；依审查白名单未打开它，
所以不能把该命中解释为可达调用，但也不能签署“全仓库无路径”。

替代写法：将 `test_cross_city_generalization.py:31-39` 改为 AST 扫描仓库全部 `*.py`（明确排除
数据、结果和环境目录），拒绝 `.bfill()` 及 `fillna(method="bfill")`/等价反向填充；若协议实际只
要求 Round 14 可达调用图，则测试名称、工作单和审查口径必须一致，并对 runner 的全部直接/间接
项目内导入做 AST 扫描。正式运行前该测试必须通过。

### R4（阻断）：三项关键测试是弱测试/假测试，未覆盖真实调用链

证据：共享支持测试在 `test_cross_city_generalization.py:61-68` 自己把同一个 `(datasets,
metadata)` 对象放进两臂字典，再断言它们相同；它没有调用 `run_station_task`，即使生产代码给两臂
传入不同支持仍会通过。H=6 测试在 `test_cross_city_generalization.py:70-84` 手工提供时间戳和
预期块标签，没有验证 `prepare_shared_data` 的真实生成链。篡改测试
`test_cross_city_generalization.py:112-158` 只改 prediction 而故意保留旧 SSE，只证明冗余 SSE
能发现非协调篡改；同时改两臂标签并重算 SSE 的攻击未覆盖。

替代写法：① mock `train_arm`/`predict`，调用 `run_station_task`，捕获两臂收到的 dataset 对象并
逐个 `assertIs`，同时验证 baseline 首先训练、ST 初始化路径等于同种子 baseline checkpoint；
② 用 H=6 的合成 frame 调用 `prepare_shared_data`，从完整确认时间轴独立计算标签后比较每个标量；
③ 新增协调篡改测试：同时改两臂块标签并重算 SSE，汇总器必须拒绝；另测时间戳、lead、metadata
支持和指纹任一篡改均拒绝。

### R5：失败状态名不符合协议 STOP/INCOMPLETE 语义

证据：协议 §9 要求门失败为 STOP，缺失/不一致/不可复现为 STOP/INCOMPLETE；汇总器却在
`summarize_cross_city_generalization.py:305-315,346-350` 将不完整矩阵或门失败统一写成
`FAIL`。异常路径虽写 verification failure（`summarize_cross_city_generalization.py:363-374`），
也不生成协议状态。

替代写法：完整两任务且全部门通过才为 `PASS`；矩阵缺失、产物非法或配置不可复现写
`INCOMPLETE`；完整矩阵但任一任务任一门失败写 `STOP`；smoke 保持 `SMOKE_NOT_ELIGIBLE`。
