## 1. 新增实现

- `baseline_models.py`：B/C 层 tsai 模型包装、信息集选择、输出形状适配、容量登记。
- `baseline_traditional.py`：A1–A6；所有拟合仅使用 train，Ridge 仅用 valid 选择 alpha。
- `baseline_training.py`：逐条复刻 legacy 训练顺序、优化器、调度器、早停、checkpoint 与评估语义。
- `run_baseline_comparison.py`：北京/广州矩阵定义、断点续跑、逐臂落盘、运行前后代码状态校验。
- `summarize_baselines.py`：仅从 NPZ 独立复算，输出 B1–B4、自检表和 BL-F1–F3。
- `test_baselines.py`：T1–T9。

没有修改任何既有代码、数据、协议、模型或研究路线文件。

## 6. 已知偏差与风险结论

1. 按工作单，基线不执行 ST 专属空间诊断与邻站干预（disable/zero/shuffle/center_copy）；其余训练语义由 T1 证明与 legacy 一致。
2. tsai 1.0.1 的 TST 在构造时会把位置编码放到默认 GPU，而其他参数初始在 CPU。包装训练在构造后统一显式 `.to(device)`；本次 ROCm 上 default/matched、单站/多站四个 TST 运行均成功，**TST 保留**。
3. tsai 1.0.1 的 PatchTST 实测返回 `[B,c_in,H]`，即使传入冻结要求的 `c_out=1`；它是通道独立主干，不做显式站间混合。包装取中心站对应输出以满足 `[B,1,H]`。因此 C1 在该库版本下是“全部通道共同执行、共享权重但中心通道输出”，不是显式跨通道融合；这是冻结协议假设与库真实语义的偏差，正式结果解释必须保留此限制。
4. 协议锁定的 plain PatchTST 实测参数量为 16,680（18 通道）/16,656（6 通道），略低于 matched 下界，故只能登记 `matched_nearest`；没有擅改主干超参。ResNet 因 tsai 构造器不暴露宽度参数，最接近档仍为 478,337，同样明确登记。
5. `default` 与 `matched` 对固定结构的 plain PatchTST、ResNet 是同一模型，因此同 seed 冒烟数字相同；保留两行用于完整容量台账，不将其伪称为不同容量实验。
6. 冒烟只有 2 epochs，所有 RMSE 仅用于可运行性与产物验证。未据此筛选模型、修改协议或启动正式矩阵。
