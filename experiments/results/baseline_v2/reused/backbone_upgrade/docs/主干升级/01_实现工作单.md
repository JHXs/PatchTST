# 主干升级实验 · 实现工作单

## 1. 冻结边界

- P1 逐 `(city, L, H, station, seed)` 展开协议期望候选全集，只读取既有产物的 `best_valid_loss`。
- 每个组合固定展开 13 行注册候选全集；候选按 `eligible / not_in_protocol_coverage / metric_missing / checkpoint_missing / invalid_validation / source_*` 显式登记；非头条或跨城市未安排的候选也保留在 `selection.csv`，不参与排序。
- P2 复原胜出主干并严格装载既有检查点，把 `BackboneAdapter` 放入 `ST_PatchTST.patch_tst`。
- `patch_tst` 全参数冻结；空间预测头保持既有零初始化，挂载起点必须与主干预测最大绝对差不超过 `1e-12`。
- P2 只训练既有 Top-5 门控、站点身份偏置与预测端有界残差分支，不重训候选主干。

## 2. 数据与资产

| 项目 | 北京 | 广州 |
|---|---|---|
| 数据准备 | `prepare_datasets_leakfree` | `load_center_candidate_frame` + `prepare_shared_data` |
| 神经候选 | 主检出 `experiments/results/baselines/beijing` | 主检出 `experiments/results/baselines/guangzhou` |
| 当前退化主干 | 无泄漏覆盖实验 worktree | 广州覆盖实验结果根；缺失检查点须显式登记 |
| P3 单站点口径 | `tables/single_station_baselines/S3_paired_detail.csv`；当前分支缺失时回退到基线 worktree绝对路径 | 同左 |

所有外部资产只读。运行器不读取候选 test 指标进行选择。

## 3. 产物与续跑

输出根为 `experiments/results/backbone_upgrade/{smoke,formal}/`：

- `selection.csv`：全部期望候选、不可用状态、验证损失和唯一胜出者；
- `raw_metrics.csv`：每个 P2 运行的状态、升级 ST/自身主干指标及诊断；
- `predictions/*.npz`：目标、升级 ST 与自身主干的 scaled/物理量预测；
- `checkpoints/*.pt`：P2 最佳验证轮次的挂载模型；
- `training_logs/*.csv`、`metadata/*.json`：训练轨迹和数据/选择溯源；
- P3 的三张逐种子配对表、诊断表、独立复算表和合规自检表。

每次 P1 选择和每次 P2 状态结束后立即覆盖写入去重 CSV。`completed`、`infeasible_oom`、`nonfinite` 均视为已落盘终态，续跑会跳过。

## 4. 异常规则

- CUDA/HIP OOM：登记 `infeasible_oom`，清理缓存后继续；
- 非有限损失：统一以协议学习率的 `1/10` 从头重试一次；仍非有限则登记 `nonfinite`；
- 其他运行时错误：不吞掉，立即失败，避免把实现错误伪装为不可行候选。

## 5. 验收顺序

1. 指定环境变量后执行 `py_compile`；
2. 执行 `test_backbone_upgrade.py` 的 T1–T7；
3. 只运行北京 24→1、seed 2047 的两轮 smoke；
4. 执行 smoke P3 汇总并独立复算；
5. 报告选择结果、对照结果、预计完整矩阵耗时；
6. 等待主代理明确批准后才运行 formal 完整矩阵。
